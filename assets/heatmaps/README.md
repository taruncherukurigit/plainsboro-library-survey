# Heatmap exports

Exported from NetSpot Android using **Export to image**, filtered to the library's
own networks only (Include/exclude networks), with the Signal level display range
set to −85 / −35 dBm before export.

## Exports

| File | Description |
|---|---|
| `ground-signal.png` | Ground floor, signal level (RSSI), −85 to −35 dBm |
| `ground-sir.png` | Ground floor, signal-to-interference ratio |
| `ground-snr.png` | Ground floor, signal-to-noise ratio. SNR map generated by NetSpot on its default 0–86 dB scale. The survey device did not expose per-point noise-floor measurements during collection; SNR values here reflect NetSpot's internal calculation rather than measured ambient noise, and should be treated as indicative only. |
| `second-signal.png` | Second floor, signal level (RSSI), −85 to −35 dBm |
| `second-sir.png` | Second floor, signal-to-interference ratio |
| `second-snr.png` | Second floor, signal-to-noise ratio. Same caveat as above — no per-point noise-floor data was available from the survey device. |

## Why SIR and SNR look similar to the signal map

Not an export error. Both ratios are derived from signal strength against a
roughly building-uniform baseline (interference sources and ambient noise don't
vary sharply by location here), so areas of strong RSSI tend to also show strong
SIR and SNR. The geometry naturally echoes the coverage map — that is expected
behaviour, not evidence of a misconfigured export.

## Method notes

- Networks filtered to `Plainsboro-Public-Library` and its associated hidden
  BSSIDs only, via Include/exclude networks, before every export.
- AP detection sensitivity left at its survey-time setting so all eight access
  points render as markers on the maps.
- SIR and SNR display ranges were left at NetSpot's default (0–86 dB) rather than
  matched to the −85/−35 dBm signal-level range, since they are a different unit
  (a ratio, not an absolute power level) and forcing the same numeric range would
  not have been meaningful.
